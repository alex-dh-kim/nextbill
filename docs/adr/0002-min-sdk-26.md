# ADR-0002: minSdk 26

- 상태: 승인 (2026-10-23)
- 출처: 설계 문서 §3.1, §6 ADR-2 [설계자 판단]

## 맥락
결제일 계산은 `LocalDate`, `YearMonth`, `LocalTime`, `Clock` 같은 `java.time` API에 기대고 있습니다. 기준점인 Now in Android는 minSdk 24이고, API 26 미만에서 `java.time`을 쓰려면 core library desugaring이 필요합니다.

## 결정
minSdk를 26으로 둡니다. compileSdk 37 / targetSdk 36은 NiA와 같습니다. `java.time`을 desugaring 없이 씁니다.

## 대안
- **minSdk 24 + desugaring (NiA 방식):** 지원 기기는 조금 늘지만 빌드 설정과 의존성(`desugar_jdk_libs`)이 하나 늘어납니다. 금지 목록에 desugaring이 있습니다.
- **kotlinx-datetime:** 라이브러리가 하나 늘어납니다. 금지 목록에 있습니다(설계 문서 §3.2).

## 결과
- 날짜·시간 계산은 `java.time`만 씁니다. 시간은 주입한 `Clock`과 `CurrentDateSource`에서 얻습니다(ADR-0012).
- API 26~27에서는 백업 구분이 불가능해 백업을 끕니다(ADR-0008).
- 직접 확인은 API 26 / 33 / 36 에뮬레이터에서 합니다(설계 문서 §9.2).
- JVM 모듈(`core:model`·`core:domain`)의 NewApi는 Lint가 아니라 `checkAndroidApi`(build-logic `AndroidApiCheck.kt`, `lintDebug`에서 실행)가 검사합니다. Lint의 ApiDetector는 Android가 아닌 모듈을 검사하지 않습니다. `LocalDate.ofInstant`(API 34)로 API 26–33에서 알림이 예약되지 않던 버그(최종 리뷰 C1) 뒤에 넣었으니 지우지 않습니다.
