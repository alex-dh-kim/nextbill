# ADR-0013: 데이터 저장과 파생 상태(알림·위젯) 갱신을 분리합니다

- 상태: 승인 (2026-10-24), 4차 리뷰(2026-10-25) 반영
- 출처: 설계 문서 §6 ADR-13 [설계자 판단]

## 맥락
구독을 저장하면 알림 재예약과 위젯 갱신이 뒤따릅니다. 갱신이 실패했을 때 저장까지 실패로 보이면 사용자가 다시 저장을 눌러 중복 저장이 생깁니다. 갱신이 동시에 여러 번 돌면 서로 다른 시점의 데이터로 알람을 덮을 수 있습니다.

## 결정
- 저장·해지·복원·삭제는 DB에 반영되면 성공입니다.
- 알림 재예약과 위젯 갱신은 앱 범위 코루틴에서 따로 실행하고, 실패해도 저장 결과를 바꾸지 않습니다. 가져오기와 앱 시작도 같습니다. 데이터 교체·복구가 확정된 뒤의 알람 갱신 실패는 가져오기 성공이나 준비 상태를 바꾸지 않고, 알람은 다음 갱신이 다시 겁니다.
- 갱신은 한 번에 하나씩 실행하고, 실행 중에 요청이 오면 끝난 뒤 최신 데이터로 한 번 더 실행합니다.
- 실패를 삼킬 때도 코루틴 취소(`CancellationException`)는 삼키지 않습니다(`runCatchingNonCancellation`).
- 저장 자체가 실패하면(DB 예외) 화면은 "저장하지 못했어요"를 보여 주고 입력을 그대로 둡니다.
- **허용한 위험:** 저장이 DB에 반영된 직후, 화면이 결과를 받기 전에 프로세스가 죽으면 복원된 입력으로 다시 저장해 같은 구독이 2건 생길 수 있습니다. 막지 않으며, 발생 빈도는 측정하지 않았습니다.

## 대안
- **저장과 갱신을 하나의 성공/실패로 묶기:** 갱신 실패가 저장 실패처럼 보여 중복 저장이 생깁니다.
- **별도 작업 큐(WorkManager):** 프로세스가 죽어도 새 프로세스의 첫 갱신이 OS 알람을 다시 걸므로(ADR-0004) 앱 시작 갱신으로 충분해 쓰지 않습니다.

## 결과
- 갱신 실패 주입, 직렬화(동시 요청 시 최신 데이터로 한 번 더), 취소 전파를 테스트합니다.
- 저장 직후 프로세스 종료로 인한 중복 가능성은 README와 이 ADR에 허용한 위험으로 남깁니다.
