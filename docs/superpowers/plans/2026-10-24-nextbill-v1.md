# NextBill v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 반복 결제를 등록하면 다음 결제일·이번 달 합계·알림·위젯·캘린더를 제공하는 오프라인 Android 앱 NextBill v1(F1~F11)을 공개 저장소에 완성합니다.

**Architecture:** Now in Android(커밋 `2982e63`)식 멀티 모듈 + Navigation 3 `api`/`impl` 분리. 도메인 규칙은 JVM 모듈(`core:model`, `core:domain`)의 순수 함수로 두고, 저장·알림·위젯·시간 같은 경계는 `core:domain`에 정의한 인터페이스를 바깥 모듈이 구현합니다(ADR-11). 화면은 Room `Flow` + 오늘 날짜 `Flow` → 도메인 함수 → 불변 `UiState`로 흐릅니다. 저장과 파생 상태(알림·위젯) 갱신은 분리합니다(ADR-13).

**Tech Stack:** Kotlin 2.3(AGP 9 내장 Kotlin), AGP 9.3, Hilt, Jetpack Compose + Material 3, Navigation 3, Room, Preferences DataStore, Glance, kotlinx-serialization-json, JUnit4·Truth·Turbine·Robolectric·Roborazzi, Spotless(ktlint), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-23-nextbill-design.md` (이하 "설계 문서"). 디자인 원본: `docs/design/stitch/` (`DESIGN.md`, 화면별 `code.html`·`screen.png`). 리뷰 대응: `docs/reviews/2026-10-24-review-response.md`.

## Review Focus

1. **늦어지고 있는 알람과 재예약:** Doze로 늦어지는 중인 A 구독 알람이 있을 때 B 구독을 저장해도 A의 알람은 그대로 남아야 합니다. 옛 브로드캐스트·중복 전달은 무시하고, 알림 문구는 예약된 결제일 기준이어야 합니다 → Task 5, 8, 13.
2. **해지·복원의 과거 기록:** 해지한 동안의 결제가 지난달 캘린더·합계에 다시 생기면 안 되고, 같은 날 해지·복원으로 결제가 두 번 세어지면 안 됩니다 → Task 3.
3. **켜 둔 화면의 날짜:** 홈·캘린더를 켠 채 자정·월말을 넘기거나 시간대를 바꾸면 "오늘", D-n, 이번 달 합계가 바뀌어야 합니다 → Task 11, 18, 19.
4. **백업 가져오기 도중 실패:** 잘못된 파일은 아무것도 바꾸지 않고, 적용 도중 프로세스가 죽으면 다음 실행에서 "전부 새것"으로 수렴해야 합니다 → Task 8, 12.
5. **금액·통화 경계:** 쉼표·소수 자릿수·큰 값 입력, 미래 시작 구독만 있는 홈, 기본 통화가 없는 합계에서 화면이 죽거나 0으로 덮이면 안 됩니다 → Task 4, 6, 18.

**Interfaces:**
- Produces: `fun violations(edges: Map<String, Set<String>>): List<String>` — 키는 모듈 경로, 값은 그 모듈이 의존하는 프로젝트 경로들. `fun isCheckedConfiguration(name: String): Boolean` — 이름이 `test`·`androidTest`·`kspTest`로 시작하지 않는 의존 설정이면 true. 루트 태스크 `checkModuleRules`는 모든 서브프로젝트에서 검사 대상 설정(`api`, `implementation`, `compileOnly`, `runtimeOnly`, `debugImplementation` 같은 variant 설정 포함)의 `ProjectDependency`를 모아 `violations`에 넘기고, 결과가 비어 있지 않으면 실패합니다.
- 검사 범위 밖(README·CLAUDE.md에 명시): 외부 라이브러리 의존, 테스트 설정. 외부 라이브러리는 카탈로그와 Task 25 점검으로 다룹니다.

규칙(설계 문서 §5.2):
1. `:core:model`은 프로젝트 의존 0개.
2. `:core:domain`은 `:core:model`만.
3. `:feature:*:impl`은 다른 feature의 `impl`을 의존하지 않음.
4. `:core:database`, `:core:datastore`는 `:core:data`만 의존할 수 있음.
5. `:feature:*`는 `:core:data`를 의존하지 않음(앱만 조립).
