# NextBill v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 반복 결제를 등록하면 다음 결제일·이번 달 합계·알림·위젯·캘린더를 제공하는 오프라인 Android 앱 NextBill v1(F1~F11)을 공개 저장소에 완성합니다.

**Architecture:** Now in Android(커밋 `2982e63`)식 멀티 모듈 + Navigation 3 `api`/`impl` 분리. 도메인 규칙은 JVM 모듈(`core:model`, `core:domain`)의 순수 함수로 두고, 저장·알림·위젯·시간 같은 경계는 `core:domain`에 정의한 인터페이스를 바깥 모듈이 구현합니다(ADR-11). 화면은 Room `Flow` + 오늘 날짜 `Flow` → 도메인 함수 → 불변 `UiState`로 흐릅니다. 저장과 파생 상태(알림·위젯) 갱신은 분리합니다(ADR-13).

**Tech Stack:** Kotlin 2.3(AGP 9 내장 Kotlin), AGP 9.3, Hilt, Jetpack Compose + Material 3, Navigation 3, Room, Preferences DataStore, Glance, kotlinx-serialization-json, JUnit4·Truth·Turbine·Robolectric·Roborazzi, Spotless(ktlint), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-23-nextbill-design.md` (이하 "설계 문서"). 디자인 원본: `docs/design/stitch/` (`DESIGN.md`, 화면별 `code.html`·`screen.png`). 리뷰 대응: `docs/reviews/2026-10-24-review-response.md`.

- 금액은 최소 단위 `Long`. 소수 자릿수는 `java.util.Currency.defaultFractionDigits`. 지원 통화는 KRW, USD, EUR, JPY. `Double`/`Float`로 금액을 계산하지 않고, 합산은 `Math.addExact`.
- 시간은 모두 주입된 `java.time.Clock`과 `CurrentDateSource`에서 얻습니다. `LocalDate.now()`/`System.currentTimeMillis()`를 인자 없이 호출하지 않습니다.
- 문자열: 기본 `values/`는 영어, `values-ko/`는 한국어. 모든 키는 두 언어에 존재합니다(lint `MissingTranslation` 오류 유지). 화면 문구의 기준은 한국어 시안입니다.
- 글꼴은 Pretendard(SIL OFL) 400/500/600/700, `res/font`. 타이포 토큰은 `DESIGN.md` 값을 그대로 씁니다.
- 일회성 UI 이벤트(Channel)로 화면을 닫거나 결과를 알리지 않습니다. 결과는 UiState로 표현하고, 화면 이동은 `Navigator.pop(key)`처럼 여러 번 불러도 한 번만 적용되는 방식으로 합니다.
- 성능 개선은 측정 근거 없이 주장하지 않습니다. `@Immutable`/`@Stable`을 컴파일러 리포트를 통과시키려고 붙이지 않습니다.
- 전 직장(museLIVE/Quabble) 자료는 참고하지 않습니다. CLAUDE.md·hook·ADR도 백지에서 씁니다.
- 실패를 격리하는 `runCatching`은 `CancellationException`을 다시 던지는 `runCatchingNonCancellation`(core:domain)으로만 씁니다.
- 알림 전달은 best effort입니다(설계 문서 ADR-14). 문서·README·테스트 이름에 "최소 1회"·"정확히 1회"·"최대 n회" 같은 전달 보장을 쓰지 않습니다.
- 앱이 OS에 거는 알람은 항상 2개 이하입니다(알림 1 + 위젯 자정 1, 설계 문서 ADR-3). 구독마다 알람을 걸지 않습니다. Android 12 AOSP 기준 앱당 동시 알람 한도는 500개입니다.
- 커밋 메시지는 영어, 의도 중심, `Co-Authored-By`·"Generated with Claude Code" 줄을 넣지 않습니다.
- 커밋은 태스크마다 하지 않고, 아래 "커밋 계획"의 지점에서만 논리 단위로 합니다. 푸시는 표에 표시한 지점에서만 합니다.

## Review Focus

1. **늦어지고 있는 알람과 재예약:** Doze로 늦어지는 중인 A 구독 알람이 있을 때 B 구독을 저장해도 A의 알람은 그대로 남아야 합니다. 옛 브로드캐스트·중복 전달은 무시하고, 알림 문구는 예약된 결제일 기준이어야 합니다. 재부팅·강제 종료로 OS 알람만 사라진 경우 다음 프로세스 시작 때 다시 걸려야 하고, 구독이 1,000건이어도 OS 알람 한도에 닿지 않아야 합니다 → Task 5, 8, 13.
2. **해지·복원의 과거 기록:** 해지한 동안의 결제가 지난달 캘린더·합계에 다시 생기면 안 되고, 같은 날 해지·복원으로 결제가 두 번 세어지면 안 됩니다 → Task 3.
3. **켜 둔 화면의 날짜:** 홈·캘린더를 켠 채 자정·월말을 넘기거나 시간대를 바꾸면 "오늘", D-n, 이번 달 합계가 바뀌어야 합니다 → Task 11, 18, 19.
4. **백업 가져오기 도중 실패:** 잘못된 파일은 아무것도 바꾸지 않고, 적용 도중 프로세스가 죽으면 다음 실행에서 "전부 새것"으로 수렴해야 합니다. 복구가 끝나기 전이나 실패한 뒤의 사용자 편집이 조용히 덮이면 안 됩니다 → Task 8, 12, 17.
5. **금액·통화 경계:** 쉼표·소수 자릿수·큰 값 입력, 미래 시작 구독만 있는 홈, 기본 통화가 없는 합계에서 화면이 죽거나 0으로 덮이면 안 됩니다 → Task 4, 6, 18.

        [(anchor, null)] 이고 d < anchor → 해지 불가(isBeforeFirstBilling). UseCase가 NOT_STARTED를 돌려주고 화면은 삭제만 제공
